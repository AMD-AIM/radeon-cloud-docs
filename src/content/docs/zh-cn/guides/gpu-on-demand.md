---
title: 按需使用 GPU
description: 启动一个免费的 CPU 工作区，只在 Notebook 运行代码时挂上 GPU。包括怎么启动、GPU 空闲后会怎样，以及怎么计费。
---

选择 **CPU 工作区 · 按需 GPU** 启动的实例是一个 CPU Notebook，本身不消耗积分。运行单元格时挂上 GPU，空闲一段时间后自动释放。只有挂着 GPU 的小时才计费。

## 启动按需 GPU 工作区

1. 打开 **首页**。
2. **部署类型** 保持 **Notebook**。
3. **GPU 使用方式** 选择 **CPU 工作区 · 按需 GPU**。
4. 在 **内核使用的 GPU 规格** 里选一个规格。之后每次挂上的 GPU 都是这个规格。
5. 点 **启动实例**。

按钮上方那一行会显示最终配置，例如 **CPU 工作区 · 按需 1 张 GPU · 挂上 GPU 时 1 积分 / 小时**。

这种工作区固定使用持久化 `/workspace` 存储，见[保存数据](/radeon-cloud-docs/zh-cn/guides/storage/)。

**独占 GPU** 就是普通实例。GPU 在整个会话期间一直占用，实例运行的每个小时都计费。

## 在 GPU 上运行代码

1. 打开实例，新建或打开一个 Notebook。
2. 内核选择 **Python 3 (GPU, on demand)**。
3. 运行一个单元格。

有空闲 GPU 时，一般几秒内就能挂上。单元格输出里会出现一行，例如 `[GPU] GPU 已挂载（用时 4 秒）。`，然后单元格在 GPU 上运行。

没有空闲 GPU 时，单元格会显示你在队列中的位置，例如 `暂时没有空闲 GPU，你在队列第 2 位，有 GPU 空出后这个单元格会自动运行。` 不用做任何操作。

JupyterLab 底部的状态栏会显示 GPU 状态，例如 **GPU ● 已挂载** 或 **GPU … 排队第 2 位**。

## GPU 空闲后

连续 30 分钟没有运行单元格，GPU 就会被释放。这是默认值，平台可能设置了别的时长。把鼠标停在状态栏的 GPU 状态上，可以看到当前的时长。

释放前不久（默认 2 分钟）会弹出提示，带两个按钮：

- **保留 GPU**：继续挂着 GPU，空闲计时重新开始。
- **立即释放**：马上释放 GPU。

GPU 释放后：

- 内存中的变量会清空。
- `/workspace` 里的文件和安装在那里的包都会保留。
- 状态栏显示 **GPU ○ 已释放 · 运行即重新挂载**。

运行任意单元格即可重新挂上 GPU。这时单元格输出会提示之前的变量已清空，把前面的单元格重新运行一遍即可。

JupyterLab 的命令面板里也有 **GPU：保留（重置空闲计时）** 和 **GPU：立即释放** 两条命令。

## 计费

- CPU 工作区不消耗积分。
- 挂着 GPU 时，每个自然小时（例如 10:00 到 11:00）计费一次，每张 GPU 1 积分。
- 同一个自然小时内释放后再挂上，不会重复计费。

积分不足时 GPU 不会挂上，单元格会显示 `积分不足，挂载 GPU 需要 1 积分。文件都还在；在 Radeon Cloud 充值后再运行即可。`

挂着 GPU 时如果积分不够支付下一个小时，GPU 会被释放，文件都会保留。充值后重新运行单元格即可。见[积分](/radeon-cloud-docs/zh-cn/guides/credits/)。

## 自动删除

CPU 工作区和其他实例一样会自动删除，时长相同，删除前也会收到同样的提示，可以点 **延长**。持久化 `/workspace` 里的文件会保留，供下一个实例使用。
